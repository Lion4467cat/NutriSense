\begin{abstract}
NutriSense is a single-image meal-analysis prototype intended to support monitoring of cooked school meals against energy and protein standards. For each capture, the current pipeline selects one food mask and predicts one dish label from its supported menu classes. It validates capture metadata, estimates metric scale from a visible reference marker, estimates portion mass, propagates uncertainty to nutrient intervals, and reports a coverage-aware compliance category for that captured serving. Because it processes only one selected dish, this result cannot establish whole-meal compliance when a meal contains multiple dishes. Its field scale reference is a 60\,mm ArUco marker printed on A4 paper. Without the marker, mapped WED dishes use a learned visual-to-mass model; an unmapped dish uses a size-prior geometry path, while an unavailable or failing learned head for a mapped dish returns \texttt{cannot\_verify}. The learned head uses a frozen DINOv2-S encoder and class-conditional regression trained on the Weight Estimation Dataset (WED). The only current dataset-based mass-estimation result is the WED development (DEV) validation carve (108 views, 21 plates, and 1,218 ground-truth regions): 15.034\,g mean absolute error (MAE), with a plate-bootstrap 95\% interval of [12.227, 18.889]\,g. A separate check evaluated leave-one-out recognition on the 46-image gallery; it is limited component evidence, not an independent test result. Project-specific real-meal capture with portion-mass annotations and evaluation remain pending; WED DEV is not a substitute for that study. This DEV result is not a locked-test result and does not measure the full image pipeline. Synthetic checks are also separate component evidence. The system is an auditable prototype; field accuracy and nutritional assumptions require physical and operational validation.
\end{abstract}

\section{Introduction}
School-meal monitoring requires more than identifying food in an image: a useful assessment must estimate served mass, translate it into nutrient quantities, and communicate uncertainty against a relevant standard. Manual weighing gives direct measurements but adds service-time work. A camera-based system can reduce that burden, yet a single image does not directly reveal metric scale, hidden food, recipe composition, or mass.

NutriSense addresses this problem as a staged decision pipeline for plated mid-day meals. It combines a printed fiducial scale reference, food-region segmentation and recognition, monocular geometry, a learned mass estimator for selected no-marker cases, probabilistic nutrient propagation, and policy rules based on PM POSHAN energy and protein minima \cite{pmposhan2022guidelines}. The output is an estimate for monitoring, not a laboratory nutrient measurement or substitute for weighing.

This paper describes the implemented pipeline and its measured-scale and no-marker paths, presents the uncertainty and coverage mechanism, and summarizes the authors' evaluation results with dataset evaluation separated from synthetic component checks. The learned mass estimator is evaluated here only on the WED development carve. No current DINOv2-S locked-test result is claimed.
\section{Related Work}
Prior ArUco work describes configurable binary-marker dictionaries and marker detection; its occlusion-handling method combines multiple markers with color-based masking \cite{garrido2014aruco}. NutriSense uses a single ID 7 marker with configured physical side length 60\,mm; the data-collection reference is an A4 PDF, distinct from a legacy A6 synthetic card.

SAM 2 is a promptable model for image and video segmentation \cite{ravi2025sam2}. NutriSense uses the official SAM 2.1 checkpoint suite to select a food mask \cite{meta2024sam2repo}, and SigLIP 2 image embeddings for gallery-first dish recognition. SigLIP 2 improves vision-language representation and localization capabilities \cite{tschannen2025siglip2}; the application abstains when gallery evidence is below its configured threshold.

MoGe-2 estimates a metric-scale point map from one image; the NutriSense runtime also calibrates predicted depth from a visible metric marker for its geometric portion path \cite{wang2025moge2}. For selected no-marker cases, a mass-regression head uses frozen DINOv2-S features. DINOv2 develops self-supervised visual representations for transfer across downstream tasks \cite{oquab2024dinov2}. The task is related to the Indian-thali WED dataset, which provides gram-level food-region measurements \cite{arun2025thali}.
\section{System Overview}
Fig.~\ref{fig:pipeline} shows the implemented single-capture sequence. Inputs are a meal image and capture/context fields. Lint gates reject invalid zoom, day, or meal band; low resolution creates a non-blocking note. The scale-anchor stage detects the reference marker. SAM 2.1 selects one food mask. SigLIP 2 compares the capture with covered menu classes in the gallery and returns one best class or abstains below the configured match threshold. The current gallery contains 46 reference images across two dish classes; this is the size of the project's gallery, not a limit of the SigLIP 2 model. With no gallery, the implementation uses text-prompt scores. Wheat products are outside the supported policy scope.

For an accepted dish, MoGe-2 predicts scene geometry. A measured marker calibrates depth scale and supports geometric portion estimation. Without a marker, the WED-trained learned head supplies grams for mapped dishes. If that head is absent or fails for a mapped dish, the pipeline returns \texttt{cannot\_verify} without grams; an unmapped dish uses size-prior geometry. Invalid inputs and stage errors also return \texttt{cannot\_verify}, while unsupported dishes return \texttt{out\_of\_scope}.

\section{Methods}
\subsection{Scale, segmentation, and recognition}
The field reference is a 60\,mm ArUco ID 7 marker printed on A4 paper. Detection returns image-space corners and metric scale. The page format is A4; the marker side, not the sheet dimensions, anchors metric measurement. When detection fails, the system records a prior anchor rather than claiming measured scale.

SAM 2.1 selects one food mask per capture. SigLIP 2 scores the supported menu classes using gallery-first visual matching and returns one best dish label; when no gallery is available, text-prompt scores provide the fallback. With a gallery, the configured similarity threshold enables abstention when no class matches strongly enough. The 46-image gallery spans two dish classes, and its 46/46 leave-one-out result is an internal gallery check, not independent test-set accuracy. The image model can score multiple candidate classes, but the current application returns only one dish classification per capture. It does not independently segment and classify every dish on a multi-item plate; therefore, its policy category describes only the selected serving and is not a whole-meal compliance determination for multi-dish meals.
\subsection{Portion mass}
On the measured path, the system estimates volume from scale-adjusted footprint area and depth above an estimated plate or vessel base, then applies effective density $\rho_{\mathrm{eff}}$:
\begin{equation}m=V\rho_{\mathrm{eff}},\qquad V\approx A_{\mathrm{metric}}\bar{h}.\end{equation}
A ring near the mask boundary can estimate a base plane. Documented table or size priors are used when geometry is unavailable and are flagged as uncertain. Densities, dish shares, vessel parameters, and prior-tier values remain assumptions pending physical validation.

For mapped no-marker dishes, the model encodes the resized full capture and pools features from a region of interest whose bounding box is derived from the selected mask. It uses a frozen DINOv2-S/14 encoder, ROI feature pooling, and class-conditional regression trained on WED. The learned mass estimate does not use monocular geometry. However, the current pipeline runs the MoGe depth stage before choosing the portion-mass path; a depth-stage failure therefore returns \texttt{cannot\_verify} even when the learned head could otherwise estimate mass. Per-class residual scale supplies mass uncertainty. If the head is missing or fails for a mapped dish, the pipeline returns \texttt{cannot\_verify} with no grams; it does not silently substitute geometry. An unmapped dish follows the size-prior geometry path. No-marker learned mass receives a 0.90 coverage factor; no-marker size-prior geometry receives a 0.60 factor, which prevents PASS and FAIL under the configured gates.
\subsection{Nutrient uncertainty and compliance}
The system samples portion mass, recipe shares, configured nutrient values, and associated uncertainty using Monte Carlo ($n=4000$, fixed seed). The two mandatory nutrients are cooked-plate energy and protein. National PM POSHAN covers Bal Vatika and classes I--VIII in eligible schools, with primary norms for classes I--V (450 kcal and 12 g protein) and upper-primary norms for classes VI--VIII (700 kcal and 20 g protein) \cite{pmposhan2022guidelines}. The application exposes three bands: classes 1--5, 6--8, and 9--10; it has no separate Bal Vatika band. Karnataka separately extended its Mid-Day Meal Scheme to classes IX--X: a state evaluation says the extension is funded from state resources, while a Karnataka administrative report records the 2007 extension order and states that IX--X receive the same nutrition content as upper primary, with matching ingredient quantities \cite{karnataka2022mdmevaluation,karnataka2022mdmreport}. NutriSense maps the IX--X band to the central upper-primary reference of 700 kcal / 20 g because the administrative report lists matching ingredient quantities; this is an application policy mapping, not a separately documented Karnataka IX--X calorie/protein norm. Classes IX--X are not part of centrally defined PM POSHAN coverage.

For each mandatory nutrient, $P$ is the estimated probability that the captured serving reaches its minimum. Coverage $C$ is a product of evidence-quality factors. PASS requires every mandatory nutrient to have $P\geq0.90$ and $C\geq0.85$. FAIL requires at least one mandatory nutrient to have $P\leq0.10$ and $C\geq0.90$. Other scoreable cases are BORDERLINE. These are screening categories for the selected serving; the single-dish pipeline cannot establish that all components of a multi-dish meal meet the per-meal minimum. Invalid inputs, unrecognized dishes, and stage failures return \texttt{cannot\_verify}; unsupported dishes return \texttt{out\_of\_scope}. No-marker responses lead with a disclaimer that mass is estimated. Salt is advisory and does not determine the verdict.
\section{Evaluation Protocol}
The authors evaluated image-region mass labels from WED, grouped by plate. The current DINOv2-S fallback result uses a 10\% validation carve from WED training plates: 108 validation views from 21 plates and 1,218 regions, selected with seed 42, with 2,000 plate-bootstrap replicates. Evaluation reads ground-truth dish classes and ROI boxes from the manifest; it isolates the mass head and does not exercise predicted segmentation, classification, or end-to-end verdict accuracy. The locked test split is protected. MAE is computed over regions:
\begin{equation}\mathrm{MAE}=\frac{1}{N}\sum_{i=1}^{N}|\hat m_i-m_i|.\end{equation}
\section{Results}
The external WED DEV fallback result for the DINOv2-S head is MAE 15.034\,g (plate-bootstrap 95\% CI [12.227, 18.889]\,g) over 1,218 regions on 21 plates. In paired evaluation on the same plates against the previous ResNet-50 head, MAE changed from 20.298 to 15.034\,g: $\Delta=-5.264$\,g (paired 95\% plate-bootstrap CI [$-6.232$, $-4.227$]). Estimated 90\% interval coverage was 0.8522 (95\% CI [0.792, 0.899]). This is development evidence and not a locked-test estimate.

The five recorded image perturbations also reduced validation MAE relative to the prior head in paired comparisons, though perspective perturbation remained harder (17.901\,g MAE). These perturbations are applied to validation images and are not naturally captured robustness data. Synthetic and gallery checks remain bounded to their own protocols.

\section{Discussion and Limitations}
The evidence supports the feasibility of combining marker-based metric scale, visual mass regression, uncertainty propagation, and explicit policy gates in one software pipeline. The learned head improves validation MAE over the prior head on the same WED plates. This result is limited to a development carve and does not establish generalization to new institutions, dishes, cameras, serving conditions, or the protected test set. Other evidence is limited to component checks: the SAM 2.1 synthetic-scene test enforces an IoU floor of 0.75, but the recorded summaries disagree on the observed value (0.97 versus 0.98), so no point estimate is claimed; synthetic volume errors were +6.6\% (plate) and +5.6\% (bowl) with a card anchor; marker-based MoGe depth calibration had 1.1\% median error on rendered validation; and the gallery achieved 46/46 leave-one-out matches. None measures real-world end-to-end performance.

Several stages remain weakly validated outside synthetic scenes. Gallery leave-one-out is small and not an independent classifier benchmark. A project-specific real-meal capture dataset with portion-mass annotations is still to be collected; the reported WED DEV result is only a fallback mass-head development check. Nutrient values, effective densities, recipe shares, vessel assumptions, no-marker calibration, coverage thresholds, and local PM POSHAN interpretation need review against measured meals and domain stakeholders. A single image can miss hidden food or confuse overlapping components. Accordingly, this work describes a software prototype, not a validated public-health measurement instrument.

Next steps are a controlled physical scale-and-weigh study, evaluation on locked data under the repository protocol, real-canteen measurements, nutrition-table validation, and coverage calibration. The A4 marker should be printed at its supplied page scale and physically checked.
\section{Conclusion}
For each capture, NutriSense converts one selected food mask and one dish classification into an estimated mass, nutrient intervals, and a coverage-aware assessment for that captured serving. It distinguishes measured scale from estimated no-marker mass and abstains when required evidence is unavailable. On the WED development carve, the DINOv2-S head achieved 15.034\,g MAE (95\% plate-bootstrap CI [12.227, 18.889]\,g), improving over its predecessor on paired development plates. Project-specific mass-annotated meal-data collection remains pending. A single-dish capture does not establish whole-meal compliance for a multi-dish meal, and the WED fallback evaluation does not establish end-to-end, test-set, or field performance; physical and real-capture validation remain necessary.
