# Reusable food appearance tools: feasibility review

**Date:** 2026-11-03  
**Scope:** research and a five-class, CPU-only appearance preview. No production model training, corpus scaling, DEV or protected-image access, or checkpoint changes.

## Decision

Use Blender as the near-term renderer and scene-assembly layer. Reuse selected external meshes only as **noncommercial visual references/proxies** until both asset rights and WED class identity are established. Do not promote the five MetaFood3D renders as labeled WED samples: four are category proxies, and all five were rescaled for framing, so their physical scale is invalid. Keep the renderer's own geometry and labels authoritative.

FoodFusion could not be run: no checkpoint is present locally and the paper's later independent evaluation reports the pretrained model was not publicly available. No substitute generative model was installed or downloaded. NutritionVerse-Synth is the strongest reference design for a later full scene renderer, but it is not a local lightweight dependency: its public framework uses Isaac Sim and a Docker/NVIDIA/NGC setup, while the current runtime has no working NVIDIA driver. Its code is MIT-licensed; asset/data terms need a separate review before reuse.

## Five-class feasibility pilot

The comparison uses the pre-existing class-surface outputs and their eligible WED TRAIN crops, plus five MetaFood3D scanned-mesh previews rendered in Blender 5.2.3 LTS with CPU Cycles. The mesh import/framing/render took about 8.4 seconds per preview on this host. Each MetaFood3D mesh was uniformly rescaled to fit the preview frame; this deliberately makes it appearance-only. Asset renders contain no generated marker pair and no usable WED depth/mass labels.

It confirms that scanned meshes can improve surface/shape richness, but nearest-category matching does not solve class identity. All output validity checks are limited to successful image decoding/rendering and recorded source/transform provenance; the MetaFood3D branch intentionally fails physical-label validity because scale, food-only mask, WED identity, density and mass are unverified.

## Audit findings and integration recommendations

### Why the current procedural classes can still look similar

The pilot’s main limitation is representation, not just lighting: most portions are low-frequency analytic height fields. Class-specific surface colors and procedural details help, but ingredients are still generated from a small family of primitives and share plate/camera/rendering assumptions. Thus same topology and smooth silhouettes dominate, while palette changes cannot create rice-grain, leaf, slice, blister, or curry-chunk structure. Blender Shader Nodes can improve material response and Geometry Nodes can scatter class-specific instances, but the instance geometry and distribution must be both food-appropriate and tied to the parent class mask. More lighting alone will not fix generic silhouettes.

### Recommended staged use

1. Keep existing analytic scene geometry as the reference path for metric depth, masks, and physical-label testing.
2. Prototype Blender as the renderer backend using the existing class registry, camera/marker metadata, seed and manifest interfaces. Render masks/depth from the exact geometry graph, not from AI postprocessing.
3. Curate legally reusable, exact-class meshes for small prototypes. Maintain class identity confidence and asset-license metadata. Treat MetaFood3D as noncommercial research only; avoid putting NC-derived images into any future commercial product dataset.
4. Use Geometry Nodes for repeatable rice grains, chopped vegetables and leaves, chapati/papad surface deformations, and heterogeneous mixtures. Render object IDs and depth from those same nodes; compute geometry volumes from instances and keep density provenance independent.
5. Revisit AI image-to-image only after a model/checkpoint with clear rights is available. Require paired render conditions and automated mask/boundary/depth agreement tests plus human class review. If the model changes the food silhouette or marker, invalidate affected labels.
6. Consider photogrammetry for a small number of missing high-value exact foods, with measured serving mass and a calibration scale captured at acquisition. It is not the primary coverage strategy for 41 classes × portion variation.

## Reproducibility and outputs

The candidate asset records and renders are local-only beneath `datasets/processed/reusable_assets_feasibility_20261103/`. The source assets remain in the ignored MetaFood3D tree; do not redistribute or commit renders/meshes without rights review.

```bash
blender -b -t 4 --python experiments/synthetic_food/reusable_assets_feasibility_20261103/render_metafood_assets.py -- \
  --mesh-root datasets/raw/marker/metafood3d/extracted/3D_Mesh \
  --output datasets/processed/reusable_assets_feasibility_20261103/metafood3d
python experiments/synthetic_food/reusable_assets_feasibility_20261103/build_comparison.py
```

The comparison consumes only the prior class-surface pilot's saved TRAIN-only source crops and RGB renders. Its pilot manifest states that WED DEV images, WED test data, LOCKED data and ArUco evaluation captures were not accessed. The new Blender script reads only five local MetaFood3D OBJ/MTL/JPG assets. Blender resizes those assets for framing; asset scale/mass labels are not carried into the result.

## Licensing and source notes

- MetaFood3D: [official dataset page](https://lorenz.ecn.purdue.edu/~food3d/) reports 637 objects / 108 food types and explicit CC BY-NC 4.0 noncommercial terms. Local file inventory and unresolved depth/volume semantics are in [`datasets/metafood3d/README.md`](../../../datasets/metafood3d/README.md).
- NutritionVerse-3D: [paper](https://arxiv.org/abs/2304.05619) reports 105 high-resolution 3D models with food name, weight and nutrition; the later dataset descriptor reports 20 food types and OBJ/PLY. Asset/data license could not be confirmed from source metadata available in this audit.
- NutritionVerse-Synth: [project page](https://saeejithnair.github.io/nvsynth/) reports 84,984 images, 7,082 scenes, 12 views, RGB/depth/semantic/instance/amodal masks and food nutrition labels. The [GitHub repository](https://github.com/saeejithnair/nvsynth) lists MIT for its source and requires Docker, NVIDIA Container Toolkit, NGC credentials and Isaac Sim; this does not establish the assets' separate reuse rights.
- Hardware: [current Isaac Sim requirements](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html) list 32GB minimum RAM and RTX 4080 / 16GB VRAM; this runtime has ~16GB RAM and its NVIDIA driver is unavailable.
- FoodFusion: [paper](https://arxiv.org/abs/2312.03540) describes a food-specific diffusion model trained on over 300,000 curated image-caption pairs. A [later CVPR Workshop paper](https://openaccess.thecvf.com/content/CVPR2024W/MTF/papers/Shin_A_Generative_Exploration_of_Cuisine_Transfer__CVPRW_2024_paper.pdf) reports that the pretrained model was not publicly available to the wider research community. No checkpoint was found in the local cache.
- Blender: [system requirements](https://www.blender.org/download/requirements/) and [license](https://www.blender.org/about/license/) identify Blender as GPL software and state user-created artwork may be used commercially; the source model/texture license remains controlling for imported assets.
- RealityScan: [official terms overview](https://www.realityscan.com/) and [EULA](https://www.realityscan.com/eula) describe the current under-$1M small-business exception and paid seat terms for larger revenue entities.
- Meshroom: [official site](https://meshroom.org/) describes a node-based pipeline with AliceVision photogrammetry; [source license](https://github.com/alicevision/Meshroom/blob/develop/COPYING.md) is MPL-2.0.

## Remaining gate

This review does **not** approve any external asset for training or scale-up. Next meaningful action is a legal/asset audit for the exact NutritionVerse archive and any FoodFusion checkpoint, followed by an exact WED-class asset selection and a label-preserving Blender prototype. Human review is still required for any visual identity claims. No production model training or full synthetic corpus generation was performed.
