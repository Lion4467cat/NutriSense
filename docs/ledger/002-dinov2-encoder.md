## Hypothesis

The deployable head's error is feature-extraction-limited: ImageNet-V2
ResNet-50 features are good but not food-specialized. DINOv2-S/14 (dense
self-supervised ViT features, 384-ch 16×16 patch grid at 224px) transfers
far stronger spatial/semantic features while staying frozen — same
roi_align → avgpool → class-conditional MLP head, same recipe as kept
ledger-001 (photometric augs + cutout remain, this entry changes exactly
ONE variable: the backbone). BatchNorm STAGE 1B concerns disappear (ViT
has no BN buffers; the eval() pin only needs to freeze dropout/droppath).

  default unchanged | "dinov2"): ViT-S/14 patch-token grid rebuilt as a
  (B, 384, 16, 16) feature map for the existing roi_align head; CLS token
  dropped; `encode(no_grad=…)` keeps the grad-efficient train path
  encoder-agnostic; `load()` reads the checkpoint's `encoder_id`.

  guard made encoder-aware (ViT asserts EMPTY BN);
  `meta["encoder"]` recorded; eval() pin applied to the ViT encoder too.

  on a keep they must be made encoder-aware before re-pinning (that edit
